Your First SPA
2–3 sessions · 4–6 hrs
HTML/CSS/JS Netlify
▾
🎯 Goal: Build a working single-page app and deploy it live to Netlify. Friends share the link with someone before the session ends.
  • Ask AI to build your app. Go to claude.ai or chatgpt.com. Use the prompt template from the "Build with AI" section below — describe a simple checklist app. Copy the full code it gives you.
  • Create your project folder in Termux. Run mkdir ~/myapp && cd ~/myapp — this makes a folder called myapp and moves you into it. All your app files live here.
  • Paste the code into a file. Run nano index.html, long-press inside Termux and tap Paste, then save with Ctrl+X → Y → Enter. You now have your app file.
  • Test it locally. Run npx serve . then open Chrome on your phone and go to http://localhost:3000. You should see your app. Tap every button and make sure it works.
  • Fix anything broken. If something doesn't work, copy the error from Chrome (3-dot menu → More tools → Developer tools → Console), paste it into the AI chat with your code, and ask it to fix it. Paste the updated code back into your file.
  • Create a GitHub repo. Go to github.com → New repository → name it "myapp" → Create. Then in Termux run the 3 commands GitHub shows you (git init, git remote add, git push).
  • Deploy to Netlify. Run netlify login (opens browser, click Authorize), then run netlify deploy --prod --dir . — in about 10 seconds you get a live URL anyone in the world can open.
  • Share the link. Send your live URL to someone right now. Opening your own app on another person's phone for the first time is the moment everything clicks.
📌 What to build: A personal daily checklist — things to do today, water intake, mood log. Pick something you'd actually use yourself. Simple and personal beats fancy and useless.

PWA Service Worker Netlify
▾

Use the Web2PWA Converter — Easiest Way
Instead of manually creating all the PWA files yourself, use this ready-made tool. Paste your index.html code in, fill in your app name and colors, and it generates all the files you need — manifest.json, sw.js, and the updated index.html — ready to download and deploy.
🔗 OPEN WEB2PWA CONVERTER →
Steps
  • Open the Web2PWA Converter at the link above. This is the fastest way — no manual file creation needed. Open it in Chrome on your Android phone or on a desktop browser.
  • Paste your index.html into the converter. Copy your entire app code from Termux (cat ~/myapp/index.html then select all and copy), paste it into the converter's input field.
  • Fill in your app details — app name, short name (shown under the icon on home screen), theme color, background color. Pick an icon or use the default. These become your manifest.json settings.
  • Download the generated files. The converter gives you the updated index.html, manifest.json, and sw.js. Download each one. On Android they go to your Downloads folder.
  • Move the files into your Termux project folder. Run termux-setup-storage first if you haven't. Then copy from Downloads: cp ~/storage/downloads/index.html ~/myapp/ — repeat for manifest.json and sw.js.
  • Create netlify.toml to prevent old cached versions being served after updates. Run nano netlify.toml and paste the config from the code block below. Save with Ctrl+X → Y → Enter.
  • Test locally first. Run npx serve . inside your project folder, then open http://localhost:3000 in Chrome. Open DevTools (3-dot → More tools → Developer tools) → Application tab → check Manifest and Service Workers show no errors.
  • Deploy to Netlify. Run netlify deploy --prod --dir . — wait for the live URL. Open it in Chrome on your phone, tap the 3-dot menu → "Add to Home Screen". Your app installs like a native app.
  • Test offline. Turn WiFi off. Open the app from your home screen icon. If it still loads — congratulations, you just built a real PWA. 🎉
💡 If you update your app later and it won't refresh on people's phones — open sw.js and change myapp-v1 to myapp-v2 (or any new name), then redeploy. This forces everyone's browser to download the new version.
js — sw.js service worker
const CACHE_NAME = 'myapp-v1'; // Bump this to bust cache!
const FILES = ['/', '/index.html', '/manifest.json'];

self.addEventListener('install', e => {
  e.waitUntil(
    caches.open(CACHE_NAME).then(c => c.addAll(FILES))
  );
});

self.addEventListener('activate', e => {
  e.waitUntil(
    caches.keys().then(keys =>
      Promise.all(keys
        .filter(k => k !== CACHE_NAME)
        .map(k => caches.delete(k))
      )
    )
  );
});

self.addEventListener('fetch', e => {
  e.respondWith(
    caches.match(e.request)
      .then(cached => cached || fetch(e.request))
  );
});
toml — netlify.toml no-cache headers
[[headers]]
  for = "/sw.js"
  [headers.values]
    Cache-Control = "no-cache, no-store, must-revalidate"

[[headers]]
  for = "/index.html"
  [headers.values]
    Cache-Control = "no-cache, no-store, must-revalidate"

Backend with Cloudflare Workers + D1
2–3 sessions · 5–8 hrs
Workers D1 Wrangler
▾
🎯 Goal: Persist real data server-side and share it across devices. Build a shared app the whole group can use.
  • Install Wrangler (Cloudflare's tool). Run npm i -g wrangler@2.21.3 in Termux. This is the specific version that works on Android — don't use a newer one.
  • Log into Cloudflare. Run wrangler login — it opens a browser link. Tap it, log into your Cloudflare account, and tap Authorize. You'll see "Successfully logged in" in Termux.
  • Create a database. Run wrangler d1 create myapp-db. Cloudflare creates a database and shows you a database_id — copy that ID, you'll need it in the next step.
  • Ask AI for your backend files. Use the "Cloudflare Worker + D1 Backend" prompt from the Build with AI section. Paste the database_id you just copied into the AI response when it shows a placeholder for it.
  • Create the 3 files. Create worker.js, wrangler.toml, and schema.sql using nano — paste each file's code from the AI and save. Check: wrangler.toml must have your real database_id.
  • Set up the database table. Run wrangler d1 execute myapp-db --file schema.sql — this creates your table in the database. If you see "Done" with no errors, it worked.
  • Deploy your backend. Run wrangler publish (not "deploy" — that's v3 syntax). You get a URL like myapp.yourname.workers.dev — this is your API.
  • Update your frontend. Open your index.html, find the part where data is saved/loaded, and ask AI to update it to call your Workers URL instead of localStorage. Test everything again.
js — worker.js pattern
export default {
  async fetch(request, env) {
    const url = new URL(request.url);
    const cors = {
      'Access-Control-Allow-Origin': '*',
      'Content-Type': 'application/json'
    };

    // Serve static index.html for non-API routes
    if (!url.pathname.startsWith('/api/')) {
      return env.ASSETS.fetch(request);
    }

    switch(url.pathname) {
      case '/api/items': {
        if (request.method === 'GET') {
          const { results } = await env.DB
            .prepare('SELECT * FROM items ORDER BY id DESC')
            .all();
          return Response.json(results, { headers: cors });
        }
        if (request.method === 'POST') {
          const { text } = await request.json();
          await env.DB
            .prepare('INSERT INTO items (text) VALUES (?)')
            .bind(text).run();
          return Response.json({ ok: true }, { headers: cors });
        }
      }
      default:
        return new Response('Not found', { status: 404 });
    }
  }
};

AI API Netlify Functions
▾
🎯 Goal: Make something feel genuinely intelligent. Call an AI API server-side (keeping keys safe) and show the result in your app.
  • Get a free Gemini API key. Go to aistudio.google.com/apikey → sign in with Google → Create API Key. No credit card needed. Copy the key.
  • Ask AI to generate a Netlify serverless function. Tell it: "I want a Netlify function at netlify/functions/ai.js that receives a prompt, calls the Google Gemini API with my key from process.env.GEMINI_API_KEY, and returns the reply as JSON."
  • Create the function file. In your project, run mkdir -p netlify/functions then nano netlify/functions/ai.js and paste the code from the block below.
  • Add your API key to Netlify (NOT to your code). Run netlify env:set GEMINI_API_KEY your-key-here — replace with your actual key. This keeps it secret on Netlify's servers.
  • Update your index.html. Ask AI to add a text input and button to your app that sends a message to /.netlify/functions/ai and shows the reply. Paste the updated code into your file.
  • Deploy and test. Run netlify deploy --prod --dir . — you must deploy to Netlify (not just local server) for the function to work. Open your live URL, type something, and see the AI respond.
js — netlify/functions/ai.js (Gemini)
export async function handler(event) {
  // Handle CORS preflight
  if (event.httpMethod === 'OPTIONS') {
    return {
      statusCode: 200,
      headers: { 'Access-Control-Allow-Origin': '*',
                 'Access-Control-Allow-Headers': 'Content-Type' },
      body: ''
    };
  }

  const { prompt } = JSON.parse(event.body);
  const key = process.env.GEMINI_API_KEY;

  const response = await fetch(
    `https://generativelanguage.googleapis.com/v1beta/models/gemini-flash-latest:generateContent?key=${key}`,
    {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        contents: [{ role: 'user', parts: [{ text: prompt }] }],
        generationConfig: { maxOutputTokens: 512 }
      })
    }
  );

  const data = await response.json();
  const reply = data.candidates?.[0]?.content?.parts?.[0]?.text
    || 'No response.';

  return {
    statusCode: 200,
    headers: { 'Access-Control-Allow-Origin': '*' },
    body: JSON.stringify({ reply })
  };
}

Git Workflow + Auto Deploy
Ongoing
GitHub Netlify CI/CD
▾
🎯 Goal: Push code → site updates automatically. No more manual deploys. This is the workflow used by professionals.
  • Connect your GitHub repo to Netlify. Go to netlify.com → Add new site → Import from Git → GitHub. Select your repo. Set the publish directory to . (just a dot — means the root folder). Click Deploy.
  • Make a small change to test auto-deploy. Open your index.html in nano, change the app title or any text, save it. Then run git add . && git commit -m "test auto deploy" && git push.
  • Watch it deploy automatically. Go to your Netlify dashboard — you'll see a new deploy starting within seconds of your push. About 30 seconds later, your live site is updated. No manual deploy needed ever again.
  • Set up a custom subdomain (free). In Netlify → Domain settings → Options → Edit site name. Change it to something meaningful like myapp-abdulbagi.netlify.app. Much easier to share than a random URL.
  • Learn the daily habit: every time you finish a feature or fix, run those 3 git commands. Think of it as saving your work to the cloud — git add . stages changes, git commit -m "what you did" saves a snapshot, git push sends it up and triggers the deploy.
  • Write meaningful commit messages. Instead of "update", write what you actually did: "add search filter to list", "fix keyboard layout on Android", "change colors to dark theme". Future you will thank present you.

Set Up GitHub SSH Key

SSH lets you push code without entering your password every time. Do this once per device.

git config --global user.name "Your Name" Set your Git identity (use your real name)
git config --global user.email "[email protected]" Set your Git email (same as GitHub account)
ssh-keygen -t ed25519 -C "[email protected]" Generate SSH key pair (press Enter 3 times for defaults)
cat ~/.ssh/id_ed25519.pub Print your PUBLIC key — copy this entire output
ssh -T [email protected] Test connection after adding key to GitHub → Settings → SSH Keys
📌 After step 4: Go to github.com → Settings → SSH and GPG Keys → New SSH Key. Paste the key there, give it a name like "My Android".

Cloudflare Workers + D1 Setup

Set up a serverless backend with a real database, all from Termux.

wrangler login Authenticate with Cloudflare (opens browser)
wrangler d1 create myapp-db Create a D1 SQLite database — copy the ID from output into wrangler.toml
wrangler d1 execute myapp-db --file schema.sql Apply your database schema
wrangler dev --local Test locally before deploying
wrangler publish Deploy to Cloudflare edge (use 'publish' on v2, not 'deploy')

Managing API Keys Safely

Never put API keys in client-side code. Here's the safe pattern for each platform.

netlify env:set MY_API_KEY your-key-here Set an environment variable in Netlify (for serverless functions)
wrangler secret put MY_API_KEY Set a secret in Cloudflare Workers (prompts for value)
echo ".env" >> .gitignore Always gitignore your .env file before committing
🔒 Rule: If the code runs in the browser, anyone can read it. API keys belong only in serverless functions (Netlify Functions or Cloudflare Workers), accessed via process.env.KEY or env.KEY.

Build with AI — No Coding Experience Needed
🤖

You don't write code — you describe what you want

This section is for non-developers. You will use AI tools (Claude, ChatGPT, Gemini) to generate all the code. Your job is to describe your app clearly, copy the output into Termux, test it, and tell the AI what to fix. That's it. This is a real workflow used by thousands of builders today.

The 6-Step Build Loop
1
📝 Describe your app to AI
Write a clear initial prompt explaining what you want to build. Include: what it does, who uses it, what data it stores, what it looks like. The more detail, the better the first result.
2
📋 Copy the code from AI
The AI gives you one or more files. Copy the code — long-press and select all in the AI chat, or use the copy button. You only need the content inside the code block (between the ``` marks).
3
📂 Paste it into Termux
Create a folder for your project, open the file in nano, paste the code, and save. Or use the clipboard method to write the file directly. Exact commands are in the "Move Code to Termux" section below.
4
🧪 Test it in your browser
Open the file in Chrome on your Android device. Check every button, every input, every feature. On Android, open Chrome and go to the file path, or use a local server. Note exactly what's broken or missing.
5
🔁 Tell AI what to fix
Go back to the AI chat. Describe what's wrong specifically. Paste any error messages exactly. The AI will give you an updated file or just the changed part. Replace and test again.
6
🚀 Deploy when happy
When the app works the way you want, push it to GitHub and deploy to Netlify. Share the live link. Repeat the loop for new features.

Moving Code from AI to Termux

Open the file in nano, clear it, paste your copied code. Works for any file size.

Method 2 — Fast

Use termux-clipboard-get to write whatever is in your clipboard directly to a file.
1. Copy code from AI chat

📖 Android Dev with Termux QUICKSTART GUIDE
You do not need a powerful computer to start learning development. Your Android phone or tablet is enough for many real projects — writing code, running servers, using Git, building websites and PWAs, and deploying apps online.
Part 1 — Install F-Droid
Step 1 — Enable Unknown Sources
  1. Open Settings
  2. Go to Apps → Special App Access → Install Unknown Apps
  3. Select your browser or file manager
  4. Enable Allow from this source
Note: Menu names may differ slightly depending on your phone brand.
Step 2 — Download F-Droid
  1. Open your browser and go to f-droid.org
  2. Tap Download F-Droid
  3. Open the downloaded .apk and tap Install
Part 2 — Install Termux
Step 3 — Install Termux from F-Droid
⚠️ Do NOT install Termux from Google Play — that version is outdated. Always use F-Droid.
  1. Open F-Droid and wait for repositories to update
  2. Tap Search and type Termux
  3. Select Termux (Terminal emulator with packages)
  4. Tap Install and confirm
Part 3 — First Time Setup
Step 4 — Select Package Mirrors
Launch Termux from your app drawer, then run:
termux-change-repo
Choose a nearby mirror and press Enter. Good mirrors improve download speed.
Step 5 — Update Packages
pkg update && pkg upgrade
This updates the Linux environment and all installed packages.
Part 4 — Install Development Tools
Step 6 — Install Essential Packages
pkg install nodejs git nano python
ToolPurpose
nodejsRun JavaScript apps and install npm packages
gitVersion control — save and sync your code
nanoSimple text editor inside the terminal
pythonPython programming and running scripts
Step 7 — Optional Useful Tools
pkg install wget curl unzip zip openssh
Useful for downloads, API calls, SSH access, and working with archives.
Part 5 — Storage Access
Step 8 — Access Internal Storage
termux-setup-storage
Tap Allow when prompted. This gives Termux access to your Downloads, Pictures, and Documents folders.
~/storage
This shortcut inside Termux points to your Android storage.

Part 7 — GitHub Setup
Step 9 — Configure Git
git config --global user.name "Your Name"
git config --global user.email "you@email.com"
Step 10 — Generate & Add SSH Key
ssh-keygen -t ed25519
Press Enter through all prompts. Then copy your public key:
cat ~/.ssh/id_ed25519.pub
Go to github.com → Settings → SSH Keys → New SSH Key, paste the output, and save. Then test:
ssh -T git@github.com
You should see: Hi username! You've successfully authenticated.

Important: Use version 2.21.3 specifically — it is the stable version for Termux on Android. Newer versions may not work.
Create a free account at cloudflare.com, then run wrangler login.

Part 10 — Common Problems
Package install fails
pkg update && pkg upgrade
Then retry the install command.
Permission denied errors
termux-setup-storage
Port already in use
Use a different port number:
python -m http.server 3000
Keyboard shortcuts not working
nano ~/.termux/termux.properties
Add this line:
extra-keys = [['ESC','CTRL','ALT','TAB']]
Then reload:
termux-reload-settings
